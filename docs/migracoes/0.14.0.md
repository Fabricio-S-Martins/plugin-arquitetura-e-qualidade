# Migração 0.14.0

Prompt para colar no Claude do projeto, com o plugin já em 0.14.0. Pré-requisito: projeto no modelo 0.13.x.

Ajustar este projeto ao que mudou no plugin arquitetura-e-qualidade 0.14.0. Regras: não alterar código, não commitar, não renomear arquivos além do que o passo 1 diz. Mover arquivos só com `git mv`. Mostrar a prévia (skill previa-diff) de cada lote (~5 arquivos) e só aplicar após meu "aprovado". Nunca inventar: dado que o arquivo não confirma, me perguntar.

O que mudou na 0.14.0: backlog e documentação passam a ter a mesma forma, e as tags de tipo passam a ser uma só por nota, com o nome do grupo como prefixo.

docs/
├── backlog/
│   ├── backlog.md
│   └── modulos/<m>/ (<m>.md, tarefas/, decisoes/)
└── documentacao/
    ├── documentacao.md
    └── modulos/<m>/ (<m>.md, api/, fluxos/)

- Fluxo ou decisão que toca 2+ módulos fica na pasta do módulo principal; a nota dos outros módulos linka (`../<principal>/fluxos/<f>.md`).
- Tags de tipo (1 por nota; substituem `tipo/...` e `grupo/...`): backlog/geral, backlog/modulo, backlog/tarefa, backlog/decisao, documentacao/geral, documentacao/modulo, documentacao/api, documentacao/fluxo. `modulo/`, `fluxo/` e `status/` continuam.
- Não alterar docs/.obsidian/graph.json (cores e visões do grafo ficam por minha conta).

Exemplo: `tags: [backlog/tarefa, modulo/autenticacao, fluxo/autenticacao-cadastro, status/concluido]`.

Passos:
1. Estrutura (docs/): propor `git mv` de docs/modulos → docs/documentacao/modulos; de docs/fluxos/<f>.md → docs/documentacao/modulos/<principal>/fluxos/<f>.md (principal = módulo que o fluxo toca primeiro; não claro → me perguntar); de docs/README.md → docs/documentacao/documentacao.md (único arquivo renomeado). Não mexer em docs/backlog, docs/sessoes e docs/runbooks.
2. Links: corrigir os links relativos quebrados pela mudança (módulo → documentacao.md, módulo → fluxos, API → módulo); nos módulos não principais, linkar o fluxo em `Fluxos` (`../<principal>/fluxos/<f>.md`). Conferir com Glob que cada destino existe.
3. Tags: em cada nota de docs/ (ignorar docs/sessoes/), substituir as tags `tipo/...` e `grupo/...` pela tag de tipo única pelo caminho: tipo/task → backlog/tarefa; tipo/decisao → backlog/decisao; tipo/backlog → backlog/geral; tipo/modulo + grupo/backlog → backlog/modulo; tipo/modulo + grupo/documentacao → documentacao/modulo; tipo/api → documentacao/api; tipo/fluxo → documentacao/fluxo; tipo/readme → documentacao/geral. Manter `modulo/`, `fluxo/` e `status/`. Nota sem tag de tipo → propor pelo caminho. Mudar só o frontmatter.
4. Conferir: nenhuma nota com tag `tipo/` ou `grupo/`, nenhuma de docs/ sem tag de tipo, nenhum link quebrado.
5. Relatório final curto: o que foi ajustado, o que ficou pendente e as dúvidas.
