O que mudou na 0.43.0:
1. **ADR passa a se chamar decisão.** A tag de grupo `adr` vira `decisao` e os estados `adr/proposta`, `adr/aceita` e `adr/substituida` viram `decisao/proposta`, `decisao/aceita` e `decisao/substituida`. Regra nova no plugin: a tag de grupo tem o nome do assunto, o mesmo do arquivo e da instrução (linguagem do projeto), sem sigla.
2. **Card e backlog passam a se chamar tarefa e tarefas.** A skill `criar-card` vira `criar-tarefa`; o template `TEMPLATE-CARD.md` vira `TEMPLATE-TAREFA.md`; a tag de grupo `backlog` vira `tarefas` (a tag de estado `tarefa/<valor>` não muda). O exemplo de estrutura passa a ser `docs/tarefas/modulos/<m>/NN-nome.md`, com os arquivos de tarefa direto na pasta do módulo, sem a subpasta `tarefas/`. Nomes de pasta são do projeto: renomear pasta ou mover arquivo só se o projeto quiser.
3. **Nada específico de linguagem ou ferramenta no plugin.** Regras retiradas do plugin:
   - A `configurar-projeto` deixou de trazer a tabela fixa de ferramentas de C# (`csharp-ls` e plugin `csharp-lsp`). Passou a conferir a lista de ferramentas do projeto: arquivo `ferramentas.md` na área de padrões (ex.: `docs/padroes/regras/ferramentas.md`; tag `padrao`; 1 linha por ferramenta: `<ferramenta> — conferir: <comando> — instalar: <comando ou link>`).
   - O `.editorconfig` opcional deixou de exigir projeto C#: vale para qualquer projeto sem o arquivo e fixa só o estilo que o código já segue.
   - Os `allowed-tools` de `executar-tarefa` e `configurar-projeto` deixaram de listar comandos `dotnet`; o comando de build é do projeto e é permitido nas permissões do próprio projeto.
   - `documentar` passou a seguir o formato de diagrama, o estilo de tabela e destaque e o contrato de API do projeto; Mermaid e o estilo anterior viram só sugestão quando o projeto não tem padrão.
4. **Pontos em aberto** (opcional): arquivo único na raiz de `docs/`, tag `ponto-em-aberto`, com achados de desvio do padrão ainda sem decisão (peneira). Registro a meu pedido grava direto; achado do Claude só como proposta, gravada com meu aceite. Leitura só minha, e do Claude a meu pedido (inclusive a triagem: aceito estrutural vira decisão e gera tarefa; aceito pontual vira exceção aceita, e tarefa se algo ainda não foi implementado; corrigir vira tarefa; o que já não existe é apagado).
5. **Exceções aceitas** (opcional): arquivo único na raiz de `docs/`, tag `excecao-aceita`, registro fixo das particularidades aceitas, uma linha por exceção com o motivo e a área entre colchetes. O Claude lê só as linhas do módulo em que está mexendo e nunca corrige nem aponta uma exceção aceita.
6. **Leitura de irmãos e linguagem do domínio.** Sem regra do tipo no projeto, as skills leem até 3 arquivos irmãos reais por tipo de alvo (o mais recente, o mais parecido e um de outra unidade); divergiram sem maioria → perguntam (antes eram até 2, ou 1 na criação de tarefa).
