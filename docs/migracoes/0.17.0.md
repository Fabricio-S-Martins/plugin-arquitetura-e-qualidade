# Migração 0.17.0

Prompt para colar no Claude do projeto, com o plugin já em 0.17.0. Pré-requisito: projeto no modelo 0.14.x, 0.15.x ou 0.16.x (qualquer mistura entre eles).

Ajustar este projeto ao que mudou no plugin arquitetura-e-qualidade 0.17.0. Regras: não alterar código, não commitar, não renomear nem mover arquivos. Mostrar a prévia (skill previa-diff) de cada lote (~5 arquivos) e só aplicar após meu "aprovado". Nunca inventar: dado que o arquivo não confirma, me perguntar.

O que mudou na 0.17.0: as tags não dependem mais das pastas. O tipo e o estado do card e da decisão viram uma tag só, e o grupo é `backlog` ou `documentacao`.

- Grupo (1 por nota): `backlog` ou `documentacao`. Substitui backlog/geral, backlog/modulo, backlog/tarefa, backlog/decisao, documentacao/geral, documentacao/modulo, documentacao/api, documentacao/fluxo e as antigas `tipo/...`, `grupo/...`, `arquivo/...`.
- Card: `tarefa/<valor>`; decisão: `decisao/<valor>`. Substituem `status/<valor>` (mesmo valor). Card: pendente, em-andamento, concluido, bloqueado, cancelado. Decisão: aberta, decidida, adiada.
- Assunto: `modulo/<m>`, `camada/<c>`, `fluxo/<f>`.
- Quem leva o quê:
  - geral: só o grupo;
  - módulo (backlog e doc): grupo + `modulo/<m>`;
  - card: `backlog` + `modulo/` + `fluxo/` + `tarefa/<valor>` (+ `camada/` se o card gera doc dessa camada);
  - decisão: `backlog` + `modulo/` (≥1) + `fluxo/` se houver + `decisao/<valor>`;
  - doc de fluxo: `documentacao` + `modulo/` + `fluxo/<nome do fluxo>`;
  - doc da API e doc de camada: `documentacao` + `modulo/` + `camada/<c>` (a API é `camada/api`).
- Não alterar docs/.obsidian/graph.json.

Exemplos:
- card: `tags: [backlog, modulo/autenticacao, fluxo/autenticacao-cadastro, tarefa/concluido]`
- decisão: `tags: [backlog, modulo/pedidos, decisao/adiada]`
- doc de fluxo: `tags: [documentacao, modulo/autenticacao, fluxo/autenticacao-cadastro]`
- doc da API: `tags: [documentacao, modulo/autenticacao, camada/api]`
- nota do módulo: `tags: [documentacao, modulo/autenticacao]`

Passos:
1. Tags: em cada nota de docs/ (ignorar docs/sessoes/), reescrever a linha `tags:` no formato acima, numa linha só. Para saber o que a nota é, usar a tag antiga (`backlog/tarefa`, `documentacao/api`...) e, se ela não existir mais (formato 0.16), o caminho e o nome do arquivo (só nesta migração). O valor de `tarefa/` e `decisao/` vem da tag `status/` que a nota já tem (a tag `status/` some). Card ou decisão sem status → card: caixas todas `[x]` → concluido, senão pendente; decisão: me perguntar. Nota de fluxo sem `fluxo/` → `fluxo/<nome do arquivo>`. Doc da API → `camada/api`. Doc técnica por projeto (Domínio, Aplicação...) → propor `camada/<c>` e me perguntar. Card que gera doc de uma camada (bloco Documentação) → propor `camada/<c>`. Nota geral e do módulo sem `fluxo/`, `camada/` nem estado. Mudar só o frontmatter.
2. Regra no CLAUDE.md: se o CLAUDE.md do projeto manda trocar a tag `status/...`, propor trocar por `tarefa/...` (prévia; não editar sem meu "aprovado").
3. Conferir: toda nota de docs/ com exatamente 1 de `backlog`/`documentacao`; nenhuma com `status/`, `backlog/`, `documentacao/`, `tipo/`, `grupo/` ou `arquivo/`; todo card com exatamente 1 `tarefa/<valor>` e toda decisão com 1 `decisao/<valor>` e ≥1 `modulo/`; nenhuma nota sem frontmatter de tags.
4. Relatório final curto: o que foi ajustado, o que ficou pendente e as dúvidas.
